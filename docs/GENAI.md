# FairTrip — GenAI Features (what, which model, how it works)

FairTrip has two layers of intelligence. Keep them separate when you present:

| Layer | Job | Model | Can it change the price? |
|---|---|---|---|
| **ML (classic)** | Estimate the typical price range and status | RandomForestRegressor (scikit-learn) | Yes, this is the source of truth |
| **GenAI (this doc)** | Explain the result, translate it, suggest words while typing | CBOW (NumPy) + Llama 3.3 70B via Groq (optional) + offline template | **No.** It only writes words about numbers the ML model already produced |

---

## 1. Feature A — Next-word suggestions (CBOW)

**Where:** Community Reports → the notes box. As you type, three chips appear: "Next word (CBOW)".

**Model:** CBOW (Continuous Bag of Words), written from scratch in NumPy (`ml/training/train_cbow.py`).
We use a one-sided window: the **3 previous words** predict the **next word**.

**How it works, step by step**
1. **Tokenise:** `"driver refused to"` → `["driver", "refused", "to"]` (lower-case words).
2. **Look up embeddings:** each word is a row of a matrix `E` (94 words × 24 numbers). Each row is a learned "meaning vector".
3. **Average the context (the "bag"):** `h = mean(E[driver], E[refused], E[to])`. Word order is ignored inside the average, which is what makes it a *bag* of words.
4. **Score every word:** `z = h · W` where `W` is 24 × 94. One score per vocabulary word.
5. **Softmax:** turn scores into probabilities, `p = exp(z) / Σ exp(z)`.
6. **Top-3:** return the three most probable words (excluding the `<s>` and `<unk>` tokens).

**Training (what happens offline):**
- Corpus: 180 short taxi/travel note sentences, built from 20 templates plus place variants. *Synthetic demo data, labelled as such.*
- Loss: **cross-entropy** `−log p(correct next word)`, averaged over all examples.
- Optimiser: **full-batch gradient descent**, learning rate 0.5, 1,500 epochs. The gradient flows back into both `E` and `W`.
- Output: `ml/models/cbow.npz` (vocabulary + both matrices) and `ml/models/cbow_metrics.json`.

**Honest results** (from `cbow_metrics.json`):
- Random 15% held-out split: top-1 ≈ **75 %**, top-3 ≈ **85 %**, against a 14 % "always predict the most common word" baseline.
- **Caveat to say out loud:** the sentences share templates, so a random split is optimistic. With a strict split by template the model drops to near baseline, because 20 templates is too little data to generalise to new phrasing. This is a limit of a prototype corpus, not of the method.

**Why CBOW (and not a big LLM) here:** it is small, fast, trains in seconds on a laptop, and shows the core idea of word embeddings clearly. It needs no API key and no internet.

## 2. Feature B — AI Trip Assistant (explanation, Marathi, negotiation line)

**Where:** Result page, the card titled "AI Trip Assistant", with an English / मराठी switch.

**What it produces:**
- A 2–3 sentence explanation of the quote, the range and the status.
- The two biggest factors from the ML model's explainability output.
- A short negotiation line for the driver (English, Hinglish, Marathi), with a copy button.

**Two paths, same output shape (`backend/app/services/explain_service.py`):**

| Path | When | Model | Notes |
|---|---|---|---|
| **LLM** | `GROQ_API_KEY` is set in `.env` | **Llama 3.3 70B Versatile** via the Groq API | Writes fluent English, Marathi and Hinglish. Asked to return JSON |
| **Offline template** | No key, or the LLM call fails | Deterministic string templates | Always works offline, so the demo never breaks |

**How the LLM path works (the "prompt engineering" part):**
1. The backend builds a small JSON of facts: city, service, distance, quote, range, status, top factors.
2. A **system prompt** sets the rules: use ONLY these numbers, never invent a price, never call the fare illegal or fraudulent, say it is an estimate, and reply in a fixed JSON schema.
3. The request uses `temperature 0.3` (less random, more consistent) and `response_format: json_object`.
4. The backend validates that every required key is present and non-empty. Anything else falls back to the template.

This pattern is called **grounded generation**: the LLM rewrites facts it is given instead of recalling facts. That is how we keep the output trustworthy.

**Why an offline fallback:** API keys, quotas and internet access fail at the worst moment (a live demo). The template keeps the feature working and makes the fallback explicit in the UI ("Generated by: Offline template").

**Marathi:** with the LLM path, Marathi comes from Llama. Offline, Marathi comes from a template written in Marathi. We did **not** use a dedicated pretrained en→mr translation model (e.g. a Hugging Face `Helsinki-NLP` model) because it needs a ~300 MB download; see "Alternatives" below.

## 3. The ML model behind the price (for the question "what is behind this?")

RandomForestRegressor: 300 decision trees, each trained on a random sample of the data. The prediction is the average of the trees.
Inputs: city, service, vehicle, distance, hour, weekday, month (one-hot encoded categories).
Held-out metrics (synthetic demo data): R² 0.972, MAE ₹52.6.
The range is the prediction ±10.2 % (relative residual standard deviation on the test set).

## 4. Turning it on

```
GROQ_API_KEY=your_key_here      # in the .env file at the project root (optional)
```
Restart the backend after editing `.env`. The Result page then shows "Generated by: Groq · llama-3.3-70b-versatile".
Get a free key at https://console.groq.com (the free tier is enough for a demo). If Groq changes its model list, set `GROQ_MODEL` in `.env`.

Train the CBOW model once:
```
cd ml/training
python train_cbow.py
```

## 5. API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/genai/next-words?text=...` | Top-3 next words for the typed text (CBOW) |
| POST | `/api/genai/explain` | Explanation, Marathi text and negotiation line for a prediction |

Invalid input (for example an unknown `status`) returns 422.

## 6. Alternatives (say these if asked "why not X?")

| Option | Pros | Cons |
|---|---|---|
| Pretrained en→mr model (Helsinki-NLP/opus-mt-en-mr) | Real translation model, offline after download | ~300 MB download; quality varies on short phrases |
| Train our own translator | Full control | Needs a large parallel corpus; not realistic in a mini-project |
| LLM API (current choice) | Fluent in all three languages | Needs a key and internet; fallback needed |
| Bigger CBOW/Word2Vec corpus | More accurate suggestions | More data to collect and label |

## 7. Likely questions

* **Is the AI setting the price?** No. The Random Forest sets the range and status. The LLM only writes text about those numbers.
* **What is an embedding?** A learned vector per word. Words used in similar contexts end up with similar vectors.
* **Why average the context?** It is the defining step of CBOW: it treats the context as a bag of word vectors, which is cheap and works well for small data.
* **What is softmax?** It turns scores into probabilities that add up to 1.
* **What does cross-entropy measure?** How much probability the model gave to the word that actually came next. Lower is better.
* **Why temperature 0.3?** Lower temperature means the LLM picks more predictable wording, which suits factual explanations.
* **What if the LLM hallucinates a number?** The prompt forbids it, the facts are passed in full, and the UI states that the numbers come from the ML model. The validation step also rejects incomplete replies.
* **Is this real Marathi quality?** The offline template is simple but correct. Llama's Marathi is usually more natural; the demo should say which path is live.
* **How would you improve CBOW?** A larger real corpus of community notes, a strict template-free evaluation split, and a bigger context window.
